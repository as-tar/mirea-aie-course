# HW12 – временные ряды: temporal split, baseline-модели и GRU-прогноз

## 1. Кратко: что сделано

- Датасет `S12-hw-dataset.csv`
- Как был организован `train / validation / test`: по времени
- Какие подходы сравнивались: `B1` (`naive-last`), `B2` (`moving-average`), `B3` (`ridge-lag-features`), `R1` (`gru-forecast`) 
- Какой подход оказался лучшим: `R1`

## 2. Среда и воспроизводимость

- Python: 3.12
- pandas / numpy / scikit-learn: 2.2.2 / 2.0.2 / 1.6.1
- torch: 2.10.0+cpu
- Устройство (CPU/GPU): CPU
- Seed: 42
- Как запустить: открыть `HW12.ipynb` и выполнить Run All.

## 3. Данные и постановка задачи

- Датасет: `S12-hw-dataset.csv`
- Целевая колонка: `target`
- Частота временного ряда: 1 час
- Горизонт прогноза: 1
- Размер датасета: 4320 rows × 2 columns
- Диапазон дат: 2025-01-01 00:00:00 - 2025-06-29 23:00:00

## 4. Temporal split и признаки

### 4.1. Разбиение по времени

- Как именно выполнен `train / validation / test`: взяты первые 70% значений, следующие 15% и оставшиеся 15%.
- Почему `random split` здесь некорректен: потому что модель должна учиться на прошлых и оцениваться на будущих данных, и случайное перемешивание здесь недопустимо.

### 4.2. Признаки для baseline-моделей

- Какие лаги использовались: `lag_1`, `lag_7`, `lag_14`
- Какие rolling-признаки использовались: `rolling_mean_7`, `rolling_std_7`
- Какие календарные признаки использовались: `dayofweek`, `hour`
- Как обрабатывались пропуски после построения лагов/rolling: все строки с пропусками были удалены.
- Использовалось ли масштабирование и где именно оно обучалось: использовался `StandardScaler`, обучался на `train`.

## 5. Модели и эксперименты (B1, B2, B3, R1)

- B1 (`naive-last`): наивный baseline, где прогноз равен последнему известному значению.
- B2 (`moving-average`): baseline на основе скользящего среднего по окну разумного размера.
- B3 (`ridge-lag-features`): `Ridge` на лаговых, rolling- и календарных признаках.
- R1 (`gru-forecast`): `GRU` на оконном представлении ряда.

Дополнительно:

- Основная метрика выбора лучшей модели: `MAE`
- Дополнительные метрики: `RMSE`, `MAPE`
- `window_size` для `GRU`: 28
- Batch size: 64
- Максимальное число эпох: 30
- Optimizer: `Adam`
- Learning rate: 0.001
- Как сохранялась лучшая модель: по минимальному `val_loss` за всё время обучения

## 7. Анализ

- Наивный baseline оказался достаточно сильным, почти вровень с лучшими решениями.
- Baseline на основе скользящего среднего показал худший результат.
- `Ridge` на признаках сработала примерно на одном уровне с наивным baseline.
- `GRU` оказалась чуть лучше `Ridge`.
- Тренд в данных достаточно заметен, что положительно отражается на прогнозе.

## 8. Итоговый вывод
